## 2. 시설 매칭 파이프라인 (64·73·19 ↔ 80·31)

```text
0. 정규화: 시설명(괄호·공백·법인표기·지점표기 제거), 주소(도로명/지번 병행, 시군구 코드 부여), 전화(숫자만)
1. 공통 ID 일치            → exact_id        (public)
2. 정규화 이름+주소 정확일치 → exact_name_addr  (public)
3. 전화번호 일치 + 같은 시군구 → exact_phone   (public, 검토 표본 추출)
4. 블로킹: 같은 시군구 AND (이름 유사도 상위 3 OR 좌표 300m 이내)
   → 후보 쌍을 UC2 LLM 판정으로              (llm_extracted)
5. 검토 큐: LLM same → 사람 승인 시 llm_reviewed / 반려 시 different
6. 어디에도 안 걸린 64 시설 → "비가맹 후보(확인 필요)"
```

규칙:

- 복수 매칭(64의 한 시설이 80의 둘 이상과 일치)은 자동 연결하지 않고 검토 큐로.
- 64에 상태 컬럼이 있으면 폐업·휴업은 후보에서 제외, 없으면 "운영 여부 미확인" 라벨.
- 결과 컬렉션 `match_results`에 단계(`matchType`), 출처 등급, 판정 근거, 검토자·일시를 기록.
- 매칭 성공률·검토 대기 수·불명 수를 데이터 안내 화면과 품질 보고서에 공개.

## 3. 강좌 추출 스키마 (UC1)

| 필드 | 값 | 사용처 |
|---|---|---|
| `age_min`, `age_max`, `grade_hint` | 정수·문자열·null | 진단 연령 축, 수요 집단 연령 일치 검사 |
| `level` | beginner/intermediate/advanced/mixed/unknown | 수요 조건 일치 |
| `attendance_rule` | all_required/selectable/unknown | 시간 일치 검사(아이디어1·2의 미해결 문제) |
| `sessions_per_week` | 정수·null | 주당 횟수 검사 |
| `shuttle` | yes/no/unknown | 이동 조건 |
| `voucher_note` | 문자열·null | 이용권 조건 표시 |
| `evidence[]` | 원문 문장 | 검토 화면, 부분문자열 검증 |
| `confidence` | high/medium/low | 검토 큐 우선순위 |

저장: `course_facts` 컬렉션에 `courseId`, `descriptionHash`, `promptVersion`, `model`, 추출 필드, `provenance(llm_extracted/llm_reviewed)`, `reviewedBy/At`. 원본 `courses` 문서는 변경하지 않고 조회 시 병합.

## 4. 품질 보고서 항목 (`data/reports/`)

- 파일별: 이름, SHA-256, 인코딩, 구분자, 행 수, 컬럼, 기준일, 이용허락 표기.
- 26: 시군구 커버리지, 분모·분자 기준시점 일치 여부.
- 80·74 조인 성공률, 실패 사유 분포.
- 74: 요일·시각 파싱 성공률, 가격 단위 확인률, **설명 길이 분포(0자·20자 미만·그 이상 비율)**.
- 64: ID·상태·업종 컬럼 유무, 좌표 결측률.
- 매칭: 단계별 건수, LLM 판정 분포, 검토 대기.
- LLM 추출: 필드별 unknown 비율, evidence 검증 통과율, 평가 세트 정확도.

숫자를 미리 채우지 않습니다. 보고서가 나온 뒤 시범 시도·종목을 정합니다.
