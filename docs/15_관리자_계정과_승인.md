# 관리자 계정·이메일 인증·가입 승인·대시보드

기준: 2026-10-30 코드 · 화면: `/admin/login`, `/admin/signup`, `/admin`

관리자 신청자가 이메일을 확인한 뒤 최고 관리자(루트)가 사용을 승인하는 구조입니다. 이 기능은 스포츠 공공데이터셋을 사용하지 않고 계정 입력·서버 설정·인증 기록을 처리합니다.

## 입력과 저장 자료

| 입력·저장 위치 | 역할 |
|---|---|
| 아이디·이메일·비밀번호 | 일반 관리자 가입 정보. 아이디와 이메일을 소문자로 정리하고 중복을 확인합니다. 비밀번호는 12~128자입니다. |
| `.env`의 `ADMIN_ROOT_USERNAME`, `ADMIN_ROOT_PASSWORD` | 별도 가입 없이 사용하는 최고 관리자 로그인 설정입니다. 일반 관리자 계정과 구분합니다. |
| `.env`의 `ADMIN_AUTH_ENABLED` | 담당자 화면·API에 로그인이 필요한지 결정합니다. 변경 후 서버를 재시작합니다. |
| `admin_signups` | 이메일 확인 전 임시 신청, 비밀번호 해시·인증 코드 해시·시도 횟수·만료 시각 |
| `admin_users` | 이메일 확인 완료 계정, 비밀번호 해시·승인 상태·신청·승인 시각 |
| `admin_sessions` | 로그인 토큰의 해시·계정·역할·만료 시각 |

아이디·이메일에는 각각 중복 방지 인덱스가 있습니다. 임시 신청과 세션에는 만료된 문서를 정리하는 인덱스가 있으며, 요청 처리에서도 만료 시각을 확인합니다.

## 가입과 승인 흐름

`가입 정보 입력 → 이메일 코드 발송 → 코드 확인 → 승인 대기(pending) → 최고 관리자 승인 → 사용 승인(approved)`

1. **가입 신청**: 아이디 형식·이메일·비밀번호 길이를 검사합니다. 이미 사용 중인 계정이나 최고 관리자 아이디와 겹치면 신청할 수 없습니다.
2. **메일 발송**: 숫자 6자리 코드를 만들어 설정된 SMTP 계정으로 보냅니다. 발송에 실패하면 오류를 반환하고 정상 신청으로 저장하지 않습니다.
3. **코드 확인**: 발송 후 10분 안에 입력해야 하며 신청별 확인 시도는 최대 5회입니다. 같은 정보로 재발송을 요청하려면 60초가 지나야 하며 새 코드로 교체됩니다.
4. **승인 대기 등록**: 코드가 맞으면 이메일 확인 완료 계정을 `admin_users`에 `pending`으로 만들고 임시 신청을 삭제합니다. 이메일 확인만으로 로그인 권한이 생기지는 않습니다.
5. **최고 관리자 처리**: 대시보드의 신청 목록을 조회하고 승인하거나 거절합니다. 승인 시 `approved`, 거절·기존 권한 회수 시 `rejected`로 바꿉니다.

권한을 회수하면 해당 계정의 기존 로그인 세션도 삭제합니다. 거절된 계정은 최고 관리자가 다시 승인할 수 있습니다. 목록에는 이메일 확인을 완료한 대기·승인·거절 계정이 표시되며, 코드 확인 전 임시 신청은 표시되지 않습니다.

## 인증 메일은 어떻게 보내나

발송 설정은 `.env`의 `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`을 읽습니다. 구글 메일 사용 시 발신 계정과 앱 비밀번호를 이 설정으로 관리하며, 코드상 기본 서버는 `smtp.gmail.com`, 포트는 587입니다.

서버는 SMTP 연결 후 STARTTLS로 암호화하고 발신 계정에 로그인해 인증 메일을 보냅니다. 비밀번호와 인증 코드의 실제 값은 문서에 기록하지 않습니다. 메일 설정이 없거나 발송할 수 없으면 가입 요청은 503 오류로 끝납니다.

## 로그인과 세션 확인

- **최고 관리자**: 입력한 아이디·비밀번호를 서버 설정과 비교하고 `root` 역할로 로그인합니다.
- **일반 관리자**: 저장된 비밀번호 해시와 비교하고 승인 상태가 `approved`인지 확인합니다. 대기·거절 계정은 로그인할 수 없습니다.
- **비밀번호 저장**: 일반 관리자 비밀번호는 무작위 소금값을 섞어 PBKDF2-SHA256으로 310,000회 계산한 해시를 저장합니다. 인증 코드도 소금값을 붙인 해시로 저장합니다.
- **세션 발급**: 무작위 로그인 토큰을 쿠키에 넣고 서버에는 토큰 해시를 저장합니다. 세션 유효기간은 발급부터 7일입니다.
- **요청별 확인**: 쿠키 토큰의 해시로 유효한 세션을 찾습니다. 일반 관리자는 현재도 승인 상태인지 확인하고, 최고 관리자는 현재 설정 계정·비밀번호에 대응하는 세션인지 확인합니다.

쿠키는 JavaScript에서 읽지 못하도록 `HttpOnly`, 다른 사이트 요청을 제한하도록 `SameSite=Lax`를 사용하며 HTTPS 설정이면 `Secure`도 적용합니다. 로그아웃은 서버의 세션과 브라우저 쿠키를 삭제합니다.

최고 관리자 아이디·비밀번호 설정을 바꾸고 서버를 재시작하면 기존 최고 관리자 세션은 현재 설정과 일치하지 않아 인정되지 않습니다. 일반 관리자 세션은 각 계정의 승인 상태·만료 여부로 판단합니다.

## 인증을 껐을 때와 대시보드 역할

`ADMIN_AUTH_ENABLED=false`이면 일반 담당자 화면과 API를 로그인 없이 사용할 수 있습니다. 그러나 **가입 신청 조회·승인·거절·권한 회수는 항상 최고 관리자 로그인이 필요**합니다. 인증 해제와 최고 관리자 권한 부여는 별개입니다.

대시보드는 지역 현황·가맹 검토·지원 방안·질문하기·데이터 관리로 이동하는 메뉴와 계정 상태·회원 승인 목록을 제공하는 화면입니다. 자체적으로 스포츠 통계나 시뮬레이션을 계산하지 않습니다.

로그인이 필요한 담당자 화면에 비로그인 상태로 접근하면 로그인 화면으로 안내하고, 인증되지 않은 API 요청에는 오류를 반환합니다. 요청 횟수 제한 등 공통 운영 규칙은 [보안과 운영 상태](18_보안과_운영_상태.md)를 참고합니다.
