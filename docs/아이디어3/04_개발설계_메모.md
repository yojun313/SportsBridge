# 가맹 빈칸 지도 — 개발 설계 메모

작성일: 2026-09-18 / 상태: 구현 전 메모. 아키텍처·디자인 원칙은 [아이디어1/04_개발설계_Commeet_참조.md](../아이디어1/04_개발설계_Commeet_참조.md)를 그대로 따르고, 이 문서는 **달라지는 부분만** 적습니다.

## 1. 그대로 가져오는 것

- FastAPI + MongoDB(Motor) + Jinja2 + 바닐라 JS, `run.py`·`app/` 구조, 포트 8010, `.env.example` 규칙.
- Commeet의 색상·카드·버튼·헤더 값, `data-theme` 다크 테마, 자산 버전 방식.
- 원본 CSV를 문자열로 읽고 선행 0 보존, `datasetVersion` staging→active 전환, 참조 프로젝트 DB·자격증명 미사용.
- 접근 로그에 요청 본문 미저장, 웹 업로드 기능 없음, 적재는 로컬 CLI.

## 3. 디렉터리 변경점

```text
app/
  services/
    matching_service.py      # 전체 시설 vs 가맹시설 매칭 (정확 일치·확인 필요 분리)
    gap_service.py           # 시군구 3축 집계, 순위
    candidate_service.py     # 비가맹 후보 필터·점수·CSV
    brief_service.py         # 동네 브리프 (P1)
  routes/
    gap_routes.py            # /api/gap, /api/gap/{sigungu}
    candidate_routes.py      # /api/gap/{sigungu}/candidates, .csv
    metadata_routes.py
  templates/
    gap_index.html, gap_detail.html, candidates.html, brief.html, data_info.html
scripts/
  inspect_datasets.py        # 파일별 인코딩·행 수·컬럼·결측·기준일 보고
  import_datasets.py         # staging 적재
  build_aggregates.py        # 시군구 집계·매칭 결과를 별도 컬렉션에 저장
```

## 4. 컬렉션 초안

- `facilities_all`: 64·73·19 원본 정규화. `source`, `sourceFacilityId?`, `name`, `nameNorm`, `address`, `addressNorm`, `regionCode`, `category?`, `status?`, `location?`, `sourceAsOf`.
- `facilities_voucher`: 80·31. 같은 구조 + `voucherType(youth/disabled)`.
- `courses_voucher`: 74·30. `facilityRef`, `sport`, `sessions[]`, `priceWon?`, `pricePeriod`, `parseFlags[]`.
- `usage_monthly`: 05·04. `facilityRef?`, `course`, `yearMonth`, `applicants`, `priceWon`.
- `region_stats`: 26·07. 원 수치와 기준시점을 그대로. 비율은 저장하지 않고 조회 시 기준시점이 맞을 때만 계산.
- `match_results`: `allFacilityId`, `voucherFacilityId?`, `matchType(exact_id/exact_name_addr/ambiguous/none)`, `datasetVersion`.
- `gap_aggregates`: 시군구별 3축 수치, 순위, 계산 불가 사유, `datasetVersion`.

정규화 규칙(시설명 괄호·공백·법인 표기 제거, 도로명·지번 주소 병행 비교)은 실제 파일을 본 뒤 `data/mappings/`에 문서화합니다.

## 5. API 초안

| 메서드·경로 | 응답 |
|---|---|
| `GET /api/metadata` | 지원 시도·시군구, 데이터 버전·기준일, 축별 계산 가능 여부 |
| `GET /api/gap?sido=` | 시군구 목록과 3축 수치·순위, 계산 불가 사유 |
| `GET /api/gap/{sigungu}` | 상세: 종목 분포, 시간대 분포, 장애인 탭 |
| `GET /api/gap/{sigungu}/candidates?category=&safety=&sort=` | 비가맹 후보, 확인 필요 목록, 매칭 성공률 |
| `GET /api/gap/{sigungu}/candidates.csv` | 같은 내용 CSV (UTF-8-SIG) |
| `GET /api/brief/{sigungu}/{sport}` | 동네 브리프 (P1) |
| `GET /health`, `GET /ready` | 상태 |

모두 읽기 전용입니다. 쓰기 API가 없으므로 CSRF·세션이 초기 범위에 없습니다. 페이지 크기·정렬 키를 화이트리스트로 제한합니다.

## 6. 테스트 항목

| 검증 | 기대 |
|---|---|
| 동명 시설·다른 주소 | 자동 매칭 없음, 확인 필요로 분류 |
| ID 일치·이름 불일치 | ID 우선 매칭 |
| 26번 기준시점 불일치 | 비율 미계산, 원 수치만 반환 |
| 요일 코드 선행 0 | 보존 |
| 시간 파싱 실패 행 | 시간 축 집계에서 제외, 제외 수 보고 |
| 재적재 | 중복 없음, 실패 시 기존 버전 유지 |
| 후보 점수 | 규칙이 응답에 함께 반환됨 (비공개 가중치 없음) |
| CSV 내보내기 | 한글 깨짐 없음, 선행 0 보존 |

## 7. 완료 기준

실제 원본을 적재해 시범 시도의 시군구 진단→후보 목록→CSV가 동작하고, 매칭 성공률·파싱 성공률이 데이터 안내 화면에 표시되며, 위 테스트가 통과한 상태. 합성 데이터만으로 채운 화면은 완료가 아닙니다.
