# 운동권 복구소 — 개발 설계

## 1. 기술 선택과 참조 범위

`/home/yojun/Commeet`의 실제 소스를 확인한 기준이다. 해당 프로젝트는 FastAPI + MongoDB(Motor) + Jinja2 + 바닐라 JavaScript 구조다. README만 보고 프런트엔드 프레임워크를 추정하지 않는다.

| Commeet 참조 파일 | 새 프로젝트에서 유지할 역할 |
|---|---|
| `run.py`, `app/config.py` | dotenv와 환경설정, uvicorn 진입점 |
| `app/main.py` | 앱 조립, 미들웨어, 정적 파일, 라우터, DB 생명주기 |

| `app/routes/event_routes.py` | JSON API 계층을 나누는 방식만 참조 |

참조 프로젝트는 읽기 전용으로 다룬다. 원본 `.env`, 인증정보, 운영 데이터, 학교 인증 정책, 로고·브랜드는 복사하지 않는다. Motor 등 패키지는 참조 프로젝트의 호환 버전과 현재 실행 환경을 개발 시작 때 확인한다. API 변경이 필요한 경우 설명하고 최소 범위로 변경한다.

개발 위치는 `/home/yojun/sports`. 문서는 `아이디어2/`에 유지하고 서비스 코드는 루트의 `app/` 등에 둔다. 기존 파일과 충돌하면 먼저 확인한다. 별도 Mongo 데이터베이스 `sports_idea2_dev`, 기본 개발 포트 `8010`을 사용한다. Commeet의 DB에 연결하지 않는다.

## 3. 데이터 적재

1. 원본 파일을 보존하고 SHA-256, 출처 URL, 다운로드일, 데이터 기준일, 이용 조건을 기록한다.
2. 인코딩·헤더·행 수·결측률·중복·기간·자료 단위를 출력한다. 실제 파일을 보기 전 원본 컬럼명을 하드코딩하지 않는다.
3. 실제 헤더 → 내부 필드 매핑을 별도 명시한다. 잘못된 행은 격리하고 무시한 건수를 보고한다.
4. 시설은 공통 ID 우선, 다음은 정규화한 이름+주소의 정확한 일치로 결합한다. 불일치·중복은 검토 목록으로 남긴다. 유사 이름만으로 자동 확정하지 않는다.
5. 가맹목록에 없는 시설은 `unmatched`이지 `not_affiliated`가 아니다. 확인된 비가맹과 미연결을 구분한다.
6. 이용현황은 별도 월별 관측값으로 저장한다. 과거 강좌와 현재 강좌를 무리하게 동일시하지 않는다.
7. 강좌 요일과 시간의 해석 가능 여부를 기록한다. 선택일인지 필수 출석일인지 모르면 계산에서 제외하거나 명시적 가정으로 전환한다.
8. 적재 검증 보고서와 버전 ID를 남긴다. 원본 누락 시 가짜 실제 데이터를 채우지 말고 합성 데모 모드만 제공한다.

공개 목록 95종의 메타데이터 JSON은 실제 강좌 CSV가 아니다. 그것을 시설·강좌 테이블로 적재하면 안 된다.

## 4. 내부 모델

아래 이름은 설계용 내부 스키마다. 제공기관 원본에 해당 컬럼이 있다는 뜻이 아니다.

| 모델 | 주요 필드와 의미 |
|---|---|
| `SourceVersion` | 상품 ID, 파일 해시, 기준일, 수집일, 원본 헤더, 단위, 이용 조건 |
| `Facility` | 내부 ID, 원본 ID, 이름, 주소, 좌표, 가맹 상태, 결합 근거, 출처 |
| `Course` | 시설 ID, 종목, 연령·수준, 수업일·시각·기간, 수강료, 해석 상태 |
| `UsageObservation` | 시설·강좌 연결, 기준월, 신청인원, 중복/단위 주석, 출처 |
| `DemandCohort` | 익명 집단 ID, 인원, 종목, 연령대·수준, 가용시간, 필요한 빈도 |
| `SupplyOption` | 하나의 완전한 강좌 패키지, 추가 수용 정원, 기간, 필요한 조치 ID |
| `AccessCondition` | 집단↔공급 옵션의 이동 가능 조건, 필요 이동시간, 근거·가정 |
| `Intervention` | 가맹·개설·이동 등 유형, 비용, 준비기간, 선행/배타 조건, 근거 |
| `Scenario` | 기간, 예산, 데이터 버전, 수요·옵션·조치, 확인/가정 사용 모드 |
| `Solution` | 선택 조치, 집단별 배정량, 비용, 미충족량, 이유, 미확인 조건 |
| `Evidence` | `public / confirmed / assumption / unknown`, 출처, 확인일, 유효기간, 설명 |

서버 DB에는 초기 MVP의 공개 카탈로그만 저장한다. 수요·시나리오는 브라우저 메모리에서 작업하고 사용자가 명시적으로 로컬 JSON 저장/불러오기를 한다. 민감한 시나리오를 자동으로 localStorage에 영구 저장하지 않는다. 서버 계산 요청은 처리 후 보관하지 않고 요청 본문을 로그에 남기지 않는다.

익명 집계도 작은 집단이면 식별 위험이 있다. 실명·전화번호·개별 주소·수급 증명·건강 정보 입력란을 만들지 않는다. 대회 공개 시연은 합성 집단만 사용한다. 다중 사용자 저장·공유는 인증·권한·보존 정책을 설계한 후 별도 단계로 진행한다.

## 5. 시간·정원·이동의 정확한 의미

- 시간대는 `Asia/Seoul`, 주간 가용시간은 월요일 0~일요일 6과 자정 이후 분 단위로 표현한다.
- 화면 격자는 30분이어도 실제 강좌 시각을 임의 반올림하지 않는다. 날짜가 있는 분석 기간 내 필수 회차 전부를 검사한다.
- 월/수/금 중 선택인지 세 번 모두 필수인지 다르다. 출석 규칙이 확인되지 않으면 자동으로 편한 규칙을 고르지 않는다.
- 공급 옵션 한 개는 계획 기간 전체를 이수할 수 있는 **완전한 강좌 패키지**다. 하루 좌석 세 개를 서로 다른 세 사람의 지속적 참여로 합산하지 않는다.
- `additional_capacity`는 그 패키지에 새로 배정 가능한 확정 또는 가정 좌석이다. 총정원이나 과거 신청인원과 구분한다. 불명은 `null`이며 0도 무한대도 아니다.
- 같은 좌석·강사·공간을 여러 옵션에 중복 배분하지 않는다. MVP에서는 운영자가 독립 공급임을 확인한 옵션 또는 단일 공통 정원으로 표현 가능한 옵션만 수용한다. 복잡한 공유 자원은 명시적인 배타 조건으로 제한하거나 ‘지원하지 않는 모델’로 거절한다.
- 집단별 인원은 분할 배정 가능한 것으로 가정하고 UI에 표시한다. 집단 전체가 반드시 함께 수강해야 하는 경우 초기 모델에서 지원하지 않는다고 표시한다.
- 이동은 담당자가 확인한 집단→시설 조건을 사용한다. 시설 주변 정류장까지의 도보시간을 출발지부터의 통학시간으로 표시하지 않는다.

## 6. 계산 엔진 — 작은 범위에서 검증 가능한 완전 탐색

MVP 상한: 수요 집단 10개, 공급 옵션 30개, 개선 조치 10개. 최대 `2^10 = 1,024`개 조치 집합을 검토한다. 범위를 넘기면 임의로 자르지 않고 입력 축소를 안내한다.

```text
각 조치 집합 S에 대해:
  비용·기간·선행·배타·공유 자원 조건 확인
  예산 초과 또는 실현 불가능이면 제외
  필요한 모든 활성화 조치가 S에 있는 공급 옵션을 활성화
  수요와 공급의 종목·연령·시간·이동·가맹 호환 관계 생성
  정수 최대유량으로 수요→공급 배정량 계산
  배정량 내림차순, 비용·조치 수·ID 오름차순으로 결과 비교
```

기본 유량 네트워크: 시작→집단(인원 상한)→호환 공급(해당 인원 상한)→종료(추가 정원 상한). 같은 공급 옵션을 복제하지 않으며 각 좌석은 한 번만 배정한다. 공통 좌석 자원을 표현할 경우 공급 이후 자원 노드로 합쳐 자원 상한을 준다. 이 단순 구조로 표현 불가능한 시간별 다중 자원 충돌은 배타 조치 제한 또는 범위 제외가 필요하다.

**조치 실행의 선행 조건**과 **공급이 유효해지는 AND 조건**을 구분한다. 예시에서 수업 개설 자체는 독립 제안 가능하지만 이용권으로 쓸 수 있는 좌석이 되려면 ‘개설 AND 가맹’이 필요하다. 잘못된 단독 효과 기반 가지치기로 둘 다 버리면 안 된다.

비용은 같은 계획 기간의 추가 비용으로 맞춘다. 월 운영비와 1회 설치비를 기간 환산 없이 합산하지 않는다. 불명 비용은 0원이 아니다. 확인 모드에서는 불명 비용·정원을 가진 조치를 확정 최적안에 넣지 않는다. 가정 모드는 가정임을 명시한다.

해가 여럿이면 최소 비용·최소 조치 수의 대안과 증분 효과를 보여준다. 입력 전체 탐색이 완료된 때만 ‘이 모델과 입력 범위에서 최적’이라고 표시한다. 시간 제한으로 중단하면 ‘발견한 실행 가능안, 최적성 미확인’으로 반환한다. 휴리스틱을 구현한 뒤 정확 최적해라고 부르지 않는다.

계산은 순수 함수로 분리하고, FastAPI 요청에서는 제한된 스레드 실행 또는 작업 관리로 이벤트 루프를 막지 않는다. 요청 크기·인원·조치 개수·연산량 상한을 둔다. 제한시간에 응답을 끝냈다고 실제 백그라운드 계산이 중단되는 것은 아니므로 내부 시간 점검도 구현한다.

## 7. 페이지·API

| 엔드포인트 | 역할 |
|---|---|
| `GET /` | 개념 설명, 데이터 기준일, 합성 데모 시작 |
| `GET /workspace` | 공급·수요·조치·결과 작업 화면 |
| `GET /api/catalog/facilities` | 지역·종목별 공개 시설, 페이지 제한 |
| `GET /api/catalog/courses` | 시설별 강좌와 불명 조건 |
| `GET /api/catalog/versions` | 출처·파일 버전·검증 상태 |
| `POST /api/scenarios/validate` | 상태 비저장 입력 검증과 경고 |
| `POST /api/scenarios/baseline` | 개선 전 연결·정원 분석 |
| `POST /api/scenarios/solve` | 제한된 조합 계산, 근거와 상태 반환 |

계산 API 입력은 임의의 DB 쿼리가 아니라 Pydantic 객체로 검증한다. 서버 카탈로그 참조는 지정된 ID만 허용한다. 음수 인원·비용, 중복 ID, 순환 선행 조건, 잘못된 시간·날짜, 없는 조치 참조를 오류 처리한다.

인쇄용 보고서는 브라우저의 현재 검증된 결과로 렌더링하고 `window.print()`를 사용한다. 초기 MVP에서 외부 문서 서비스나 PDF 서버를 추가할 필요는 없다. API 오류는 Commeet처럼 JSON `detail`과 적절한 상태코드, 페이지 오류는 HTML로 나눈다.

## 8. 디자인 가이드

Commeet의 실제 CSS 기준으로 색·간격·라운딩·명확한 입력 흐름을 참조한다.

| 토큰 | 기준 |
|---|---|
| 주요색 | `#c80150` |
| 보조색 | `#34495e` |
| 배경 / 카드 | `#f9f9f9` / 흰색 |
| 기본 글자 / 테두리 | `#333` / `#ddd` |
| 카드 | 반경 8px, 내부 간격 20px |
| 버튼 | 반경 6px, 글자 15px, 패딩 11px 18px |
| 컨테이너 / 헤더 | 최대 1400px, 좌우 20px / 높이 72px |
| 글꼴 | Noto Sans KR, Pretendard, 시스템 대체 글꼴 |

`data-theme` 기반 다크 모드 구조를 유지하되 텍스트 대비를 검증한다. 실제 로고나 학교명을 사용하지 않는다. 기본 화면은 왼쪽 조건 입력, 오른쪽 현재·개선 후 비교이며 좁은 화면에서는 세로 배치한다.

공개값·담당자 확인·가정·불명을 색만으로 구분하지 말고 텍스트 배지를 함께 쓴다. 결과의 가장 큰 숫자 옆에 ‘모델상 배정량’과 ‘가정 포함’을 표시한다. 표·작은 조건 관계도 중심으로 구현하며 지도가 없어도 모든 기능이 동작해야 한다.

## 9. 검증과 완료 기준

필수 자동 테스트:

- 가상 예시: 현재 2, A만 2, B만 2, A+B 10. 80만 원 미만에서는 A+B 불가.
- 비용이 같은 동률의 결정 순서와 입력 순서를 바꿔도 같은 결과.
- 조치 단독 효과만 보는 탐욕 선택이 놓치는 결합 사례, 결합 효과가 없는 일반 사례.
- 수요 인원·정원 보존, 두 집단의 동일 좌석 이중 사용 방지.
- 공유 자원·배타 조치·순환 조건·개설 지연·기간 불일치.
- 필수 회차 일부만 시간 일치하는 경우 탈락, 잘못된 요일 문자열 검출.
- 불명 정원·비용을 0이나 무한대로 처리하지 않음.
- 동일 시설의 명칭 차이·주소 중복·조인 실패가 임의 확정되지 않음.
- 확인 모드와 가정 모드의 명확한 분리, 공개 보고서의 합성 표시 보존.
- API 상한·비정상 JSON·음수·과도한 요청에 안전한 오류 응답.

검증은 합성 fixture와 실제 CSV의 품질 검사를 분리한다. 테스트 통과는 데이터의 현실 정확도나 실제 참여 증가를 증명하지 않는다. 실제 입력·파일 버전·알고리즘 버전을 보고서에 기록한다.

완료란 원본 업로드 → 품질 검사 → 공급 탐색 → 익명 수요·조치 입력 → 현재/개선 비교 → 근거와 미확인 사항이 있는 인쇄까지 재현 가능한 상태다. 데이터 없이 화면만 만든 경우 ‘합성 데모 완료’라고만 보고한다.
