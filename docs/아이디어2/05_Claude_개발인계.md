# Claude 개발 인계 — 운동권 복구소

작성일: 2026-09-18

아래 내용을 Claude에게 전달한다. 데이터가 도착한 다음 시작하면 실제 컬럼에 맞춰 개발할 수 있다. 원본이 없으면 합성 시연을 만들 수 있지만 실데이터 연동 완료로 보고하면 안 된다.

## 그대로 전달할 요청

> `/home/yojun/sports/아이디어2`의 기획 문서를 읽고 ‘운동권 복구소’ MVP를 구현해줘. 개인 운동 추천이 아니라, 지자체가 스포츠강좌이용권 공급 공백을 개선하기 위해 ‘가맹 + 수업 개설 + 이동 지원’ 중 함께 필요한 조합을 계산하는 서비스야.
>
> `/home/yojun/Commeet`의 실제 FastAPI 서버 아키텍처와 디자인을 참조해. FastAPI + MongoDB + Jinja2 + 바닐라 JS 구조를 유지하고, React나 Next.js로 바꾸지 마. Commeet 원본·환경파일·DB·브랜드는 변경하거나 복사하지 말고 별도 설정과 DB를 사용해.
>
> 개발 전에 작업 경로의 기존 파일과 AGENTS.md를 확인하고, `README.md`, `01_데이터_다운로드_가이드.md`, `02_기존서비스조사_차별성.md`, `03_서비스_기획서.md`, `04_개발설계_Commeet_참조.md`, `06_전체데이터_검토결과.md`를 읽어. 실제 데이터가 없거나 중요한 해석이 불가능하면 그 상태를 알려주고, 사실과 가정을 분리해서 개발해.
>
> 핵심 기능은 최대 10개 개선 조치의 조합을 탐색하고, 조건을 충족한 강좌의 추가 정원 안에서 익명 수요를 배정하는 거야. A 또는 B 단독으로는 효과가 없지만 A+B에는 효과가 있는 시나리오를 반드시 구현·테스트해. 정렬된 시설 추천 목록만 만들면 안 돼.
>
> 공개 카탈로그는 서버 DB에 저장하되 시제품의 수요·시나리오는 비저장 계산과 사용자 선택 로컬 JSON 저장 방식으로 구현해. 주민 실명·개별 주소·건강정보 입력은 필요 없어. 합성 데이터는 모든 화면·출력에서 표시하고 실제 참여 성과처럼 표현하지 마.
>
> 단계별로 구현하고 자동 테스트·실제 데이터 품질 검사·브라우저 확인 결과를 보고해. 작업 종료 때 실제 구현한 것, 실제 검증한 것, 남은 가정과 실행 명령을 구분해서 알려줘. 외부 배포·시설 연락·신청·유료 서비스 사용은 하지 마.

## 단계별 산출물

### 단계 0 — 현황 확인

- 작업 트리와 기존 파일을 확인한다. 아이디어1·아이디어2 문서를 훼손하지 않는다.
- 참조 서버의 라우터/서비스/스키마/DB/템플릿/정적 파일 구성을 직접 읽는다.
- 데이터 유무·형식·이용 조건과 컬럼 정의서 유무를 보고한다.
- 실제 데이터와 가상 시나리오를 어디서 구분할지 먼저 정한다.

### 단계 1 — 데이터 검증

- 다운로드 가이드 필수 4종부터 프로파일링한다.
- 원본 해시·기준일·행 수·결측률·중복·필드 매핑을 기록한다.
- 시설·강좌 결합률과 실패 사례를 보고한다. 목표 결합률을 사실처럼 만들어 적지 않는다.
- 조사 메타데이터 JSON을 원본 CSV로 착각하지 않는다.
- 시범 지역·종목은 데이터 품질을 본 뒤 선택한다. 좋은 시연을 위해 불편한 미확인 값을 삭제하지 않는다.

### 단계 2 — 계산부터 구현

- DB나 UI에 의존하지 않는 호환 판정·조합 계산 함수를 작성한다.
- 수요→공급 최대유량과 조치 집합 완전 탐색을 사용한다.
- 가상 예시 및 예외 테스트를 통과시킨다.
- 단독 효과 탐욕 방식과 비교해 결합 조치 누락을 재현한다.
- 지원하지 않는 공유 자원·분할 불가 집단은 입력 단계에서 안내한다.

### 단계 3 — 서버 및 화면

- 공개 카탈로그 조회, 시나리오 검증·기준선·계산 API를 구현한다.
- Jinja2 공통 레이아웃과 Commeet 스타일 토큰을 사용한다.
- 공급 탐색 → 수요·개선 조치 편집 → 대안 비교 → 근거·인쇄의 흐름을 구현한다.
- 마우스 없이 주요 입력을 조작할 수 있고 모바일에서 표가 깨지지 않는지 확인한다.

### 단계 4 — 재현·발표 준비

- 실제 공공데이터 버전과 합성 예시 버전이 구분된 데모를 제공한다.
- 실행 방법, 필요한 환경변수, 적재 방법, 테스트 방법을 루트 개발 README에 기록한다.
- 대회 발표용으로 현재 2→A만 2→B만 2→A+B 10의 합성 시나리오를 저장한다.
- ‘모델상 배정량’, ‘미확인 조건’, ‘가정 의존 결과’를 인쇄에도 보존한다.
- 데이터 품질·테스트·수동 브라우저 검증 결과와 미완료 항목을 정리한다.

## 절대 넘기면 안 되는 해석 경계

| 하면 안 되는 것 | 올바른 처리 |
|---|---|
| 신청인원 = 고유 주민 수·출석·미충족 수요 | 원자료 단위의 과거 신청 기록으로만 표시 |
| 가맹목록 미매칭 = 미가맹 확정 | 가맹 여부 확인 후보 |
| 주변 정류장 도보시간 = 전체 이동시간 | 시설 주변 구간으로 한정 |
| 정원 없음 = 충분한 빈자리 | 불명, 확정 배정에서 제외 |
| 비용 없음 = 무료 조치 | 불명, 예산 최적화에서 확정 선택 불가 |
| 수업 목록 = 현재 개설·모집 보장 | 기준일과 운영 확인 상태 함께 표시 |
| 안전등급 = 폐쇄 가능성·사고확률 | 점검 당시 참고 정보 |
| 합성 입력에서의 개선 = 실제 정책 성과 | 입력 가정하의 시뮬레이션 |
| 경쟁서비스 미발견 = 세계 최초 | 조사 범위 내 동일 조합 미확인 |

## 개발 전에 사용자에게 필요한 것

지금 바로 필요한 것은 **필수 4종의 최신 원본과 컬럼 정의서**다. 파일을 모두 받기 어렵다면 시설·강좌 2종부터 구조를 확인하고 이용현황·전국시설을 이어 받는다.

실제 기관의 익명 수요와 시설 추가 정원·비용을 확보하지 못했더라도 공개 데이터 기반 합성 시뮬레이터는 개발할 수 있다. 다만 실제 효과 검증은 보류한다. 현장 연락이나 데이터를 외부로 전송할 필요가 생기면 별도 요청을 받는다.
