# AI 정보 추출과 시설 판정 보조

기준: 2026-10-30 현재 코드. 자유롭게 적힌 강좌 설명을 연령·출석 규칙 등 일정한 항목으로 정리하고, 규칙만으로 구분하기 어려운 시설을 보조 판정하는 운영 기능입니다. 공통 CSV 반영 때 항상 자동 실행되는 기능은 아닙니다.

## 입력 자료와 결과

| 작업 | 입력 | 구조화된 결과 | 저장 위치 |
|---|---|---|---|
| 강좌 설명 추출 | 이용현황 강좌에 연결한 강좌표의 강좌명·설명 | 최소/최대 연령, 학년 표현, 수준, 출석 규칙, 주당 횟수, 셔틀, 이용 조건, 근거 문장, 확신도 | `course_facts` |
| 시설 동일성 판정 | 가맹시설과 전체 시설 후보의 이름·주소·전화·업종 등 | 같은 시설/다른 시설/불확실, 이유, 충돌 항목 | `match_results`의 보조 판정 및 `review_queue` |
| 시설 분류 | 전체 시설의 이름·업종·유형·구분 | 추정 종목, 아동 강좌 적합성, 확신도, 이유 | `facility_class` |

시설·강좌는 [공통 가공](01_데이터셋과_공통_가공.md)으로 정리된 자료를 사용합니다. AI가 원본에 없는 실제 정원·비용·현재 모집 여부를 확인하는 기능은 아닙니다.

## 강좌 설명을 처리하는 순서

1. 강좌명과 설명을 데이터 영역에 넣고, 원문에 없는 내용은 `null` 또는 `unknown`으로 두도록 요청합니다. ‘초등 저학년’ 같은 표현을 임의로 나이로 바꾸지 않고 학년 표현으로 남기도록 합니다.
2. 응답을 정해진 스키마로 받습니다. 예를 들어 출석 규칙은 전 요일 필수·요일 선택·미확인 중 하나로 제한하고, 필드 형식을 검사합니다.
3. AI가 제시한 각 근거 문장이 실제 설명에 포함되는지 확인합니다. 없는 근거가 있으면 `evidence_not_in_text`, 최소 연령이 최대 연령보다 크면 `age_range_inverted` 표시를 남기고 확신도를 낮춥니다. 오류값을 자동으로 바로잡지는 않습니다.
4. 결과를 `llm_extracted` 상태로 저장합니다. 확신도가 낮거나 오류 표시가 있거나, 출석 규칙이 추출됐거나 최소 연령이 있으면 `needsReview`로 표시해 검토 대기 자료도 만듭니다.
5. 검색과 지원 방안 초기값은 `llm_reviewed` 상태의 연령·출석 규칙만 조건으로 사용합니다. 추출만 된 결과가 확정 조건으로 바로 적용되지는 않습니다.

예를 들어 설명에 ‘만 8~12세, 월·수·금 모두 출석’이 명시됐다면 최소 8세·최대 12세·전 요일 필수로 정리하도록 요청하고 해당 원문을 근거로 보관합니다. 이는 설명을 구조화한 결과이며 실제 지원 자격을 인증한 결과가 아닙니다.

설명 길이가 20자 미만이면 단건 추출 함수는 외부 호출 없이 미확인 기본값과 짧은 설명 표시를 반환합니다. 대량 작업의 대상 선택은 이런 짧은 설명을 아예 건너뜁니다.

## 단건 API와 대량 JSONL의 차이

| 경로 | 처리 방식 |
|---|---|
| `POST /api/llm/extract-course` | 강좌 ID로 현재 자료를 찾고 외부 모델에 한 건 요청합니다. 응답을 후검사해 저장하고 필요한 항목을 검토 대기 자료에 추가합니다. |
| `scripts/llm_extract_courses.py --online` | 지역·시도별 대상을 골라 단건 함수를 반복 실행합니다. |
| 같은 스크립트의 `--submit` | 요청 한 건을 JSON 한 줄로 만든 JSONL 파일을 올리고 Batch 작업을 제출합니다. 요청마다 강좌 ID를 넣어 결과와 연결합니다. |
| 같은 스크립트의 `--collect` | 완료된 결과 파일을 줄마다 읽어 상태 코드·거부·출력 텍스트·스키마를 검사합니다. 성공한 결과는 같은 근거·연령 후검사를 거쳐 저장합니다. |

거부 응답은 기본 미확인 결과와 거부 표시로 남길 수 있으며, 응답 오류·파싱 실패는 수집 실패 건수로 구분합니다. 대량 작업의 제출과 수집은 별도 명령입니다. 제출했다고 즉시 검색 조건에 적용되는 구조가 아닙니다.

## 시설 판정 보조는 어떻게 사용하나요?

**동일성 판정 스크립트**는 규칙으로 확정하지 못한 목록 연결 후보 중 가장 위의 후보 한 곳을 비교합니다. 이름·주소·전화·종목·업종을 모델에 보내 같은 시설인지 판정합니다. `same`이나 `unsure`는 검토 대기 자료로 보내고, ‘같음’이라고 답해도 자동으로 시설을 확정 연결하지 않습니다. 이미 판정한 항목은 다시 호출하지 않습니다.

**시설 분류 스크립트**는 같은 지역의 정상운영 시설 중 가맹 목록 연결이 없고 규칙상 아동 강좌 적합성이 미확인인 시설을 대상으로 합니다. 시설명·업종·유형·구분으로 추정 종목과 적합성을 요청해 별도 컬렉션에 저장합니다.

현재 후보 조회 코드와 화면은 이 `facility_class` 결과를 읽어 점수·규칙 판정을 바꾸거나 자동 표시하지 않습니다. 스크립트에 남은 설명과 달리, **결과 저장용 보조 코드와 실제 화면 반영 범위를 구분**해야 합니다.

## 현재 검토·승인 기능의 연결 상태

`review_service`에는 검토 항목 승인·반려 함수가 남아 있습니다. 강좌 추출을 승인하면 상태를 `llm_reviewed`로 바꾸고 일부 값을 수정할 수 있으며, 시설 동일성 승인은 목록 연결 결과를 수정하는 구조입니다.

그러나 현재 앱에는 **`/review` 화면과 승인 API 라우터가 연결되어 있지 않습니다.** 따라서 이 문서의 ‘검토 대기’는 DB에 기록된 상태를 뜻하며, 현재 웹 화면에서 해당 자료를 승인할 수 있다는 뜻은 아닙니다. 승인 연결이 없는 상태에서 새 추출 결과가 저절로 검토 완료가 되지는 않습니다.

## 비용·재호출·신뢰 범위

- 모델·프롬프트 버전·사용 가능 여부·일일 예산은 공통 클라이언트에서 관리합니다. 호출 전에 기록된 당일 비용과 예상 비용을 비교하고, 한도를 넘으면 중단합니다.
- 사용 토큰·캐시 토큰·추정 비용을 `llm_calls`에 기록합니다. 비용은 코드의 가격표로 계산한 참고치이며 실제 청구액을 확인한 값은 아닙니다.
- 강좌 일괄 스크립트는 같은 데이터 버전에서 강좌·설명 해시·프롬프트 버전이 같으면 대상에서 제외합니다. 단건 API에 같은 결과를 무조건 재사용하는 캐시가 있는 것은 아닙니다.
- 시설 분류는 해당 버전의 저장된 시설을 건너뜁니다. 공통 원본 반영과 별도로 운영자가 선택해 실행하는 작업입니다.
- 근거 포함 검사와 스키마 검사는 의미 전체의 사실 확인이 아닙니다. 근거 목록이 비어 있는 것 자체를 오류로 잡지도 않으며, 확신도가 높아도 현재 시설 상황을 보장하지 않습니다.
