# 접근 제어·요청 제한·운영 상태 확인

기준: 2026-10-30 코드

이 기능은 스포츠 데이터를 분석하는 계산이 아니라, 웹 요청을 받아 허용 여부를 확인하고 운영 상태를 알려주는 공통 처리입니다. 판단에는 요청 주소·헤더·쿠키, 서버 설정, 관리자 세션과 데이터 버전 기록을 사용합니다.

## 요청이 처리되는 흐름

1. **접속 주소를 확인합니다.** 요청의 Host가 `ALLOWED_HOSTS`에 포함되는지 검사합니다. 목록 밖의 주소는 거절하며, 운영 설정은 HTTPS 주소와 명시적인 허용 호스트를 요구합니다.
2. **로그인 상태를 읽습니다.** 쿠키 토큰의 해시로 DB 세션을 찾고 만료·계정 승인·역할을 확인합니다. [관리자 계정과 승인](15_관리자_계정과_승인.md)에서 자세히 설명합니다.
3. **담당자 경로인지 구분합니다.** 지역 현황·가맹 검토·지원 방안·질문하기·데이터 관리 등의 담당자 경로는 인증 설정에 따라 로그인을 요구합니다.
4. **변경 요청을 확인합니다.** POST·PUT·PATCH·DELETE 요청은 출처 확인용 헤더와 요청 크기를 검사합니다. 요청 종류별 횟수 제한도 적용합니다.
5. **해당 기능을 실행합니다.** 각 API가 입력 형식과 실제 조회·계산을 처리하고 결과 또는 오류를 만듭니다.
6. **브라우저 보호 설정을 붙입니다.** 응답에 콘텐츠·프레임·스크립트·캐시 관련 헤더를 붙여 돌려줍니다.

등록되지 않은 주소·메서드 조합은 라우터가 404·405 등으로 처리합니다. FastAPI의 자동 API 안내 주소 `/docs`, `/redoc`, `/openapi.json`은 앱 설정에서 비활성화되어 있습니다.

## 변경 요청과 과도한 사용은 어떻게 구분하나

| 검사 | 현재 처리 |
|---|---|
| 사이트 출처 | `Sec-Fetch-Site`가 `cross-site` 또는 `same-site`인 변경 요청을 거절합니다. |
| 요청 확인 헤더 | 변경 요청에는 `X-Requested-With: XMLHttpRequest`가 필요합니다. 화면의 공통 API 호출 코드가 붙여 보냅니다. |
| 요청 크기 | 숫자로 된 `Content-Length`가 필요하며 일반 요청은 2MiB, CSV 업로드 경로는 별도의 큰 한도를 적용합니다. 업로드 파일 처리는 데이터 관리 기능에서도 확인합니다. |
| 희망 등록·시설 의견 | 접속 IP 기준 같은 제한 묶음으로 시간당 30회까지 받습니다. |
| 비로그인 AI 질문 | 접속 IP 기준 시간당 10회까지 받습니다. 관리자 로그인 상태면 이 공통 제한을 적용하지 않으며 AI 호출 예산 등 별도 제한은 유지합니다. |
| 관리자 인증 시도·가입·메일 확인 | 인증 API와 보호 경로에서 각각의 요청 횟수를 제한합니다. |

로그인이 필요한 화면의 비로그인 GET 요청은 로그인 화면으로 안내합니다. 비로그인 API 요청은 401 오류를 반환합니다. `ADMIN_AUTH_ENABLED=false`이면 일반 담당자 접근의 로그인 요구를 해제하지만, 가입 승인·권한 회수의 최고 관리자 역할 검사는 유지합니다.

## 응답에 붙이는 보호 설정

스크립트 실행은 기본적으로 같은 사이트의 파일과 요청마다 발급한 **nonce**가 붙은 스크립트로 제한합니다. 템플릿의 인라인 스크립트에는 그 요청의 nonce를 넣습니다. 외부 사이트가 화면을 프레임으로 삽입하지 못하게 하고, MIME 형식 추측과 불필요한 출처 전송을 제한하는 헤더도 사용합니다.

카메라·마이크·위치 접근은 허용하지 않으며, HTTPS 설정에서는 HSTS를 붙입니다. API·담당자 경로·실행 기록·이벤트 응답은 `no-store`로 표시해 브라우저 캐시에 보관하지 않도록 합니다. 이 설정이 데이터 내용의 정확성까지 보증하지는 않습니다.

## 결과와 오류는 어떻게 전달하나

| 응답 범주 | 예시 의미 |
|---|---|
| 200·303 | 정상 조회·처리 또는 로그인 화면으로 이동 |
| 400·404·405·422 | 허용되지 않은 호스트·잘못된 주소/메서드·입력 형식 오류 등 |
| 401·403 | 로그인 필요 또는 역할·요청 확인 조건 미충족 |
| 411·413·429 | 요청 크기 헤더 없음·크기 초과·요청 횟수 초과 |
| 500·503 | 내부 처리 오류 또는 DB·데이터·필수 기능 설정 준비 안 됨 |

API 오류는 JSON으로 전달하고 일반 페이지의 404·500은 오류 화면으로 보여줍니다. 입력 검증 오류에서는 제출한 원문 값 등을 덜어내고, 예상하지 못한 API 내부 오류는 상세 예외 대신 일반 오류 문구를 반환합니다.

## 상태 확인과 메타데이터

- **`GET /health`**: 앱이 요청을 받아 응답할 수 있으면 `status: ok`를 반환합니다. DB 연결이나 데이터 존재는 검사하지 않습니다.
- **`GET /ready`**: DB에 ping을 보내고 현재 사용 데이터 버전이 지정되어 있는지 확인합니다. DB 불가 또는 사용 버전 없음은 503, 둘 다 준비되면 버전과 함께 `ready`를 반환합니다.
- **`GET /api/metadata`**: 사용 버전·반영 시각·파일 식별값 일부·집계기간·시도/시군구 목록·AI 설정 상태·기능 표시용 정보를 반환합니다. 화면의 지역 선택과 기준일 안내에 사용합니다.

`ready`나 메타데이터의 기능 표시가 모든 원본·행·시설의 완전성이나 실제 운영·모집 상태를 검사하는 것은 아닙니다. 데이터가 없는 기능은 조회 과정에서 별도로 오류나 빈 결과를 반환할 수 있습니다.

## 서버 안에서 공유하는 상태

로그인 세션·계정은 DB에 보관하지만 요청 횟수 제한은 **프로세스 메모리**에 보관합니다. 여러 서버 프로세스가 있으면 요청 횟수를 하나로 합산하지 않으며 재시작하면 메모리 기록이 초기화됩니다.

진행 이벤트를 보내는 구독 목록과 AI 실행 중 상태도 프로세스 메모리입니다. 같은 프로세스의 화면에 진행을 전달하지만, 여러 프로세스 간 공유나 재시작 후 진행 복원까지 제공하는 저장소는 아닙니다. 영구적인 질문 기록·데이터 반영 기록과 구분합니다.
