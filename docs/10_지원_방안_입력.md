# 지원 방안 입력·불러오기·저장

기준: 2026-10-30 코드 · 화면: `/scenario`

지역의 수요 집단·강좌·개선 조치·예산을 한 묶음으로 작성하는 기능입니다. 공개 자료는 초기값을 제공하고, 담당자가 확인한 정원·비용·시간으로 보완한 뒤 [시뮬레이션과 조합 비교](11_시뮬레이션과_조합_비교.md)에 전달합니다.

## 예시 입력값을 불러와 바로 계산

상세 입력은 항상 표시됩니다. 사용방법의 **예시 입력값 불러오기**에서 아래 네 가지 중 하나를 선택합니다. 현재 데이터 버전에서 실제 시설·강좌·시간표·수강료가 확인되는 자료를 조회하고, 지역·종목·집단·시간·연령·이동·강좌·정원·조치·비용·예산·제목과 확인 상태를 모두 채우므로, 이후에는 **조합 계산**만 누르면 됩니다.

| 예시 입력값 | 현재 → 지원 후 배정 | 조치 비용 |
|---|---|---:|
| 기존 강좌 정원 추가 | 4명 → 12명 | 30만 원 |
| 이동 지원 | 0명 → 6명 | 15만 원 |
| 정원 추가와 이동 지원 | 0명 → 8명 | 45만 원 |
| 두 집단의 정원 추가 | 8명 → 14명 | 30만 원 |

`GET /api/scenarios/presets`가 집계기간 내 실제 강좌 중 시간표 연결이 모호하지 않고 수강료가 있는 두 강좌를 고릅니다. 서버는 네 조합의 입력 검증과 배정 인원·비용을 실제 엔진으로 확인한 뒤 반환합니다. 화면에서는 검증한 입력값을 브라우저에 저장하고 최종 계산 버튼으로 이동합니다. 기존 작성 내용이 있으면 교체 전에 확인합니다. 강좌·시설명·시간표·수강료·마지막 기록월은 공개 자료이며 희망 인원·추가 정원·비용·예산·이동 조건, 자료에 없는 연령·출석 규칙은 가정입니다. 선택 지역에 적합한 강좌가 없으면 다른 지역으로 대체하며 화면에 지역 변경을 안내합니다. 확인 가능한 실제 강좌가 없으면 오류를 표시하고 가상 강좌로 대체하지 않습니다. 선행·동시 선택 불가 조건이 없는 항목은 화면에 ‘없음’으로 표시하고 내부에는 빈 목록으로 저장합니다. 각 조합을 선택하면 ‘무엇을 비교하는지’, ‘현재 상태(가정)’, ‘추가하는 지원(가정)’, ‘결과를 읽는 방법’을 별도로 표시합니다. 공개 자료의 강좌 정보와 계산용 가정을 구분해 설명합니다.

## 어떤 데이터가 들어오나

| 자료 | 불러오는 내용 |
|---|---|
| 스포츠 강좌이용권 이용현황·시설·이용시설 강좌 | 기존 시설·강좌·월 수강료·마지막 기록월·연결된 시간표 |
| 담당자가 검토한 AI 추출 정보 | 기존 강좌의 대상 연령·출석 규칙. 미검토 정보는 확인된 조건으로 사용하지 않음 |
| 전국체육시설현황 및 안전·교통·목록 연결 결과 | 가맹 검토 기능이 선정한 시설 후보와 검토 근거 |
| 서비스의 희망 강좌 등록 | 지역·종목·요일·시간대별로 묶은 집단 초기값 |
| 담당자 입력 | 실제 검토할 인원·추가 수용 정원·조치 비용·수업 일정·이동 가능 여부 |

원본을 다시 파싱하지 않고 현재 사용 버전의 가공된 조회 데이터를 읽습니다. 집단·강좌·조치는 각각의 ID로 연결하며, 비용·정원에는 공공자료·담당자확인·가정 등의 출처·확인 상태를 붙입니다.

## 불러오기에서 입력 화면까지

1. **지역·종목을 선택합니다.** `GET /api/scenarios/supply`로 해당 지역·종목의 초기 자료를 요청합니다.
2. **기존 강좌 최대 20개를 추가합니다.** 집계기간에 기록이 있는 강좌를 마지막 기록월·마지막 신청 인원 순으로 가져옵니다. 시간표·수강료는 채우지만 추가 수용 정원은 자료에 없어 미확인으로 둡니다.
3. **가맹 검토 시설 최대 5곳을 추가합니다.** 시설마다 신설 예정 강좌와 ‘가맹 협의 + 강좌 신설’ 조치 쌍을 만듭니다. 신설 조치에는 가맹 협의 조치가 선행 조건으로 들어갑니다.
4. **등록 희망을 최대 10개 집단으로 묶습니다.** 같은 종목·요일 집합·시간대의 등록을 집계하고 등록 건수가 많은 집단부터 넣습니다. 시간은 시간 단위로 묶어 표시하므로 실제 인원·정확한 시간은 담당자가 확인해야 합니다.
5. **작성 중인 내용에 합칩니다.** 같은 ID로 이미 들어온 항목은 다시 추가하지 않습니다. 지역을 바꾸거나 다시 불러와도 기존 내용이 자동 삭제되지는 않습니다.

불러올 희망 집단도 없고 작성한 집단도 없으면 **8명짜리 가정 집단**을 기본 예시로 넣습니다. 실제 이용자 8명이 등록했다는 의미가 아닙니다.

후보의 신설 시간표·정원·조치 비용은 빈칸입니다. 후보를 미가맹·신설 상태로 넣는 것도 검토를 위한 초기 설정이며, 실제 미가맹이나 개설 가능성을 확인한 결과가 아닙니다.

## 담당자가 보완할 항목

| 입력 영역 | 중요한 의미 |
|---|---|
| 수요 집단 | 익명 구분 이름·인원·종목·연령·주당 횟수·이용 가능 시간·이동 조건. 등록 건수는 중복 등록을 포함할 수 있어 실인원으로 확정하지 않음 |
| 대상 강좌 | 전체 정원이 아닌 **이번 수요를 추가로 받을 자리**, 출석 규칙·연령·시간표·가맹 상태·개설 상태·집단별 이동 가능 여부 |
| 개선 조치 | 가맹 협의·강좌 신설·정원 추가·이동 지원, 적용할 시설·강좌·집단, 비용, 필요한 선행 조치와 동시 선택 불가 조치 ID |
| 예산·계산 방식 | 조치 비용 합계의 상한과 정원 적용 여부. 빈 예산은 한도 없음, 0원은 비용 0원인 조합만 최선 후보로 검토 |

**월 수강료와 조치 비용은 별개**입니다. 조치 예산은 협의·신설·정원 추가·이동 지원에 입력한 비용의 합계에 적용합니다. 비용과 정원이 빈칸이면 미확인이며, ‘가정’으로 표시하는 것만으로 숫자가 채워지지 않습니다. 확인한 값과 시험용 가정값을 구분해야 합니다.

## 정원 중복 입력을 피하는 예시

신설 강좌를 8명 규모로 검토한다면 강좌의 추가 수용 정원은 **0**, 강좌 신설 조치의 정원은 **8**로 입력합니다. 계산은 강좌 정원에 조치 정원을 더하므로 양쪽에 8을 넣으면 16명으로 계산됩니다.

기존 강좌에 이미 추가 수용 가능한 자리가 2개 있고 조치로 6개를 늘린다면 강좌 2 + 정원 추가 조치 6 = 8자리입니다. 빈칸과 0을 혼동하지 않아야 합니다.

## 검증과 비교 화면으로 이동

`검증`은 `POST /api/scenarios/validate`로 입력 형식·개수·조치의 연결 ID 등을 확인합니다. 최대 **수요 집단 10개·대상 강좌 30개·개선 조치 10개**를 받습니다.

존재하지 않는 강좌·집단·선행 조치 연결이나 정원·비용 모드의 신설 정원 누락 등은 오류로 표시합니다. 기존 강좌의 정원·가맹 상태·시간표·출석 규칙과 조치 비용 미확인은 별도 확인 목록으로 표시합니다. 이 검증이 현재 영업 상태나 입력값의 사실 여부를 확인하는 것은 아닙니다.

`조합 계산`은 검증을 통과하면 작성 내용을 저장하고 비교 화면으로 이동합니다. 오류가 없더라도 미확인 정원·비용 때문에 배정이나 최선 후보에서 제외될 수 있습니다. 정원 미적용 비교는 사람 수가 아닌 연결 가능한 집단 수를 비교합니다.

## 저장과 JSON 파일

- 작성 내용은 현재 브라우저 `localStorage`의 `vgp_scenario`에 저장하고, 같은 브라우저에서 다시 엽니다. 서버에 시나리오 보관함을 만드는 방식은 아닙니다.
- `JSON 내보내기`는 현재 집단·강좌·조치·예산을 파일로 내려받습니다. 다른 브라우저에서는 그 파일을 불러와 사용할 수 있습니다.
- `JSON 불러오기`는 JSON을 읽어 **현재 작성 내용을 교체**하고 화면을 다시 엽니다. 파일을 읽었다고 계산 형식 검증까지 통과한 것은 아니므로 다시 검증합니다.
- `새로 만들기`는 현재 작성 내용을 초기화합니다. 필요하면 먼저 내보내기로 보관합니다.
- 검증·계산·문서 요청 시에는 입력한 시나리오가 서버로 전송됩니다. 브라우저 저장과 서버 계산을 구분하고 개인 이름·연락처는 입력하지 않습니다.
