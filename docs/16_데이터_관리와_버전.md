# 데이터 관리·원본 교체·서비스 반영·버전

기준: 2026-10-30 현재 코드 · 화면 `/data`

원본 CSV를 관리하고, 이를 서비스 조회용 데이터로 다시 만드는 기능입니다. **원본 파일 교체와 조회 데이터 반영은 별도 단계**이며, 새 CSV를 올리기만 해서는 강좌·시설 검색 결과가 바뀌지 않습니다.

## 사용하는 데이터와 표시 정보

| 정보 | 읽는 곳 | 의미 |
|---|---|---|
| 원본 10종의 이름·제공기관·역할·필수 여부 | 코드의 데이터 등록소 | 서비스가 기대하는 원본 목록 |
| 원본 존재·크기·수정일 | 서버의 원본 파일 디렉터리 | 현재 보관된 CSV 또는 gzip 압축 CSV의 파일 상태 |
| 반영 당시 원본 식별값·크기 | 현재 데이터 버전의 DB 기록 | 그 버전을 만들 때 사용한 파일의 SHA-256·바이트 수 |
| 출처 주소·기준일·메모 | 기본 등록소 + `dataset_sources` 수정값 | 데이터 관리 화면의 출처 안내 정보 |
| 버전·건수·상태 | `datasets`, `catalog_state` | 현재 사용 버전과 과거 반영 작업 기록 |
| 진행률·처리 메시지 | 서버 메모리의 작업 상태 | 현재 또는 마지막 실행 작업의 단계별 진행 정보 |

원본 10종의 내용과 파싱·시설/강좌 연결 규칙은 [공통 데이터 가공](01_데이터셋과_공통_가공.md)을 참고합니다. 이 화면은 원본 관리와 반영 작업의 시작·상태 확인을 담당합니다.

## 원본 변경과 출처 편집

- 목록은 현재 파일의 크기·수정 시각과 현재 버전의 반영 기록을 나란히 보여줍니다. 수정 시각은 원본 내용의 기준일이 아닙니다.
- **‘원본 크기 변경’은 현재 크기와 반영 당시 크기가 다른지 비교한 결과**입니다. 매번 현재 파일의 SHA-256을 다시 계산해 내용까지 비교하는 기능은 아니므로 같은 크기의 내용 변경을 놓칠 수 있습니다.
- 화면의 SHA-256 앞 10자리는 반영 당시 원본 파일의 식별값입니다. 현재 파일의 내용이 그때와 같다는 보증이 아닙니다.
- 출처 편집은 주소·원본 기준일·메모를 DB에 저장해 기본 안내값 위에 덧씁니다. 주소는 HTTP/HTTPS 형식을 검사하며, 편집만으로 파일을 내려받거나 CSV·조회 데이터를 수정하지 않습니다.

## CSV를 올릴 때의 처리

1. **올릴 대상을 고릅니다.** 등록된 데이터 키만 허용하고, 파일명 확장자가 `.csv`인지 확인합니다. 데이터 반영 작업이 진행 중이면 업로드를 거절합니다.
2. **임시 파일로 저장합니다.** 약 1MB씩 읽어 크기와 SHA-256을 계산하면서 원본 디렉터리의 임시 파일에 씁니다. 크기 제한은 1,200MiB입니다.
3. **UTF-8 형식을 일부 확인합니다.** 앞 4KB를 UTF-8/BOM 기준으로 검사하고, 경계에서 잘린 한글 바이트를 보정합니다. 파일 전체의 인코딩·열 구조·업무 내용을 이 단계에서 모두 검증하지는 않습니다.
4. **대상 CSV를 교체합니다.** 임시 파일을 등록된 표준 파일명으로 바꿉니다. 같은 파일 하나의 교체는 원자적으로 처리하고 실패한 임시 파일은 정리합니다.
5. **기존 gzip 파일은 남깁니다.** 같은 데이터의 `.csv.gz`가 있어도 삭제하지 않습니다. 원본 탐색에서는 풀어 놓은 `.csv`를 우선 사용합니다.

사용자가 올린 임의의 파일명을 서버 경로로 그대로 사용하지 않습니다. 업로드가 끝나도 현재 서비스의 조회 버전은 유지되며 ‘전체 다시 적재’를 별도로 실행해야 합니다.

## 전체 반영 작업의 흐름

1. **중복 실행을 막습니다.** 현재 서버 프로세스에서 이미 실행 중이면 새 작업을 시작하지 않습니다. 인증이 켜져 있으면 관리자 권한을 확인합니다.
2. **백그라운드 작업을 시작합니다.** 요청을 오래 붙잡지 않고 작업 스레드에서 `run_import`를 실행합니다. 새 버전 식별값은 기본적으로 UTC 실행 시각으로 만듭니다.
3. **원본을 다시 가공합니다.** 필수 5종의 존재를 확인한 뒤 지역 → 가맹시설 → 강좌 → 전체 시설·안전·교통 → 목록 연결 → 지역 통계 순으로 만듭니다. 나머지 보충 자료는 없을 수 있습니다.
4. **새 조회 데이터를 임시 컬렉션에 씁니다.** 지역·시설·강좌·월별 이용현황·시설 연결·지역 통계를 새로 저장하고, 각 컬렉션을 순서대로 교체한 뒤 인덱스를 만듭니다.
5. **사용 버전을 적용합니다.** 완료된 버전을 ‘사용 중’으로 기록하고 현재 조회 버전을 가리키는 값을 바꿉니다. 종전 버전의 작업 기록은 ‘이전 버전’으로 표시합니다.

AI 질문·추출 작업을 실행해야 데이터 반영이 완료되는 구조는 아닙니다. 기본 원본 파싱·연결·집계는 코드로 처리합니다.

## 진행률과 버전 이력

- 데이터 관리 화면은 SSE로 작업 이벤트를 받고, 약 5초마다 상태를 조회해 보완합니다. 단계 이름·메시지·경과 시간·처리 기록을 표시합니다.
- 다른 화면의 상단 공통 바는 상태를 조회합니다. 작업 중 약 2초, 평소 약 15초 간격이며, 반영 완료 후 새로고침 안내를 표시합니다.
- 진행률은 단계별로 정한 비율입니다. 원본 행을 정확히 몇 퍼센트 읽었는지나 남은 시간을 예측한 값이 아닙니다.
- 현재 진행 상태는 서버 프로세스의 메모리에 있고 다른 브라우저에서 같은 상태를 봅니다. 서버 재시작 뒤에도 같은 진행 상태가 복구된다는 보장은 없습니다.
- 버전 이력은 DB에서 최근 최대 8개 작업의 상태·반영 시각·단계별 건수를 읽습니다. 현재 버전의 통계와 과거 작업 기록을 보여줄 뿐, **과거 데이터로 되돌리는 버튼은 없습니다.**

## 간단한 예시와 한계

가정으로 새 강좌 CSV를 올리면 먼저 서버 파일만 바뀝니다. ‘전체 다시 적재’를 실행해 성공한 후 새로고침하면 새 시간표와 통계가 조회됩니다. 출처 기준일만 수정했다면 데이터 내용은 달라지지 않습니다.

잘못된 열·내용은 업로드가 성공해도 가공 단계에서 오류를 일으킬 수 있습니다. 컬렉션 교체는 각각 이루어지므로 작업 전체가 하나의 트랜잭션은 아니며, 중간 실패 시 모든 자료가 자동 복원된다고 가정하면 안 됩니다. 실패 상태와 원본·조회 결과를 확인한 뒤 문제를 수정해 다시 반영해야 합니다.
