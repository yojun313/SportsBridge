# 희망 강좌·시설 이용 희망 등록

기준: 2026-10-30 현재 코드 · 화면 `/user/voice`, 강좌 검색 결과의 등록 버튼

이용자가 원하는 종목·시간이나 이용하고 싶은 시설을 남기면, 담당자가 공급을 검토할 때 참고할 **등록 건수**로 모으는 기능입니다. 실제 수강 신청·예약·시설 가맹 신청을 처리하지 않습니다.

## 입력과 데이터 출처

| 구분 | 입력·사용 정보 | 저장·활용 |
|---|---|---|
| 희망 강좌 | 지역·희망 종목·요일·시작/종료 시각·연령·이용 유형 | 연령을 연령대로 바꿔 `demand_signals`에 등록 |
| 검색 결과에서 희망 강좌 등록 | 현재 검색 조건 | 위 정보에 월 예산·이동 수단 등을 함께 저장할 수 있음 |
| 시설 이용 희망 | 전체 체육시설 목록의 시설 ID·희망 종목 | 실제 시설의 지역 코드를 확인해 `facility_votes`에 등록 |
| 등록 대상 시설 목록 | 전국체육시설현황·공공체육시설 등과 가맹 목록 연결 결과 | 같은 시군구의 가맹 확인 후보를 표시. 거리순이나 미가맹 확정 목록은 아님 |

희망 의견은 공개 CSV를 가공한 수강 신청 이력과 **별도 데이터**입니다. 시설 선택에 공개 목록을 사용하지만, 희망 등록 건수를 원본 CSV에서 가져오지는 않습니다.

## 저장까지의 처리 흐름

1. **입력 형식을 검사합니다.** 지역 코드는 5자리, 종목은 최대 3개, 연령·시간·예산은 정해진 범위로 받습니다. 전용 등록 화면은 종목 한 개와 선택한 요일에 공통으로 적용할 시간을 보냅니다.
2. **나이를 연령대로 바꿉니다.** 12세 이하 아동, 13~18세 청소년, 19~64세 성인, 65세 이상 고령, 미입력은 미확인으로 저장합니다. 전용 화면의 연령대 선택도 대표 나이를 보낸 뒤 이 규칙으로 변환합니다.
3. **희망 강좌를 한 건 추가합니다.** 전체 희망 종목 배열과 첫 번째 대표 종목, 이용 시간, 연령대, 유형·예산·이동 수단·메모·등록 시각을 저장합니다. 정확한 나이·이름·주소는 별도 필드로 저장하지 않습니다.
4. **시설 희망은 시설을 먼저 확인합니다.** 현재 데이터 버전의 전체 시설 목록에 해당 ID가 있어야 등록됩니다. 지역은 요청자가 보낸 값보다 실제 시설의 지역 코드를 사용합니다.
5. **새 합계를 돌려줍니다.** 화면의 건수를 갱신하거나 등록됨 표시를 하고, 이후 지역 현황·가맹 검토·지원 방안에서 참고합니다.

## 어떤 방식으로 집계하는가

| 표시 항목 | 실제 계산 |
|---|---|
| 지역 희망 강좌 총건수 | 해당 지역의 저장 기록 수 |
| 같은 종목 등록 | 검색한 종목 중 하나라도 저장된 희망 종목 배열에 있는 기록 수 |
| 종목별 등록 | 각 기록의 **첫 번째 종목**으로 묶어 건수를 세고 상위 8개 표시 |
| 희망 시작 시간대 | 각 이용 가능 구간의 요일과 `시작 분 ÷ 60`의 정수값으로 집계. 화면은 상위 8개 표시 |
| 시설 이용 희망 | 시설 ID별 기록 수를 합산. 지역 요약에는 전체 합계와 상위 5개 시설 포함 |

한 등록에 월·수요일이 있으면 시간대 통계에 월요일 1건, 수요일 1건으로 각각 포함됩니다. 종료 시각이나 수업 시간 전체를 시간대별로 펼쳐 세지는 않습니다.

## 담당자 기능으로 전달되는 방식

- **가맹 검토:** 시설의 기본 점수에 희망 등록 1건당 1점을 더하되 최대 3점까지만 더합니다. 등록이 10건이어도 가점은 3점입니다.
- **지원 방안:** 같은 종목·요일 집합·시작/종료 시간대를 묶어 등록이 많은 상위 10개 수요 집단을 만듭니다. 각 집단의 `인원` 초기값은 실제 사람 수가 아니라 등록 건수입니다.
- 시뮬레이션용 집계는 시간을 시간 단위 대표 구간으로 단순화합니다. 요일마다 다른 시간도 하나의 시작·종료 범위로 합칠 수 있어 실제 조건을 확인해 수정해야 합니다.
- 불러올 때 이동·준비 여유는 0, 이동 수단은 자력 이동, 주당 횟수는 미입력으로 설정합니다. 연령대 통계는 포함하지만 정확한 최소·최대 나이를 자동 확정하지 않습니다.

## 중복 억제와 집계 범위

- 검색 결과의 등록 버튼과 시설 희망 버튼은 성공 후 현재 화면에서 비활성화됩니다. 전용 희망 강좌 폼에는 동일 조건을 다시 제출하지 못하게 하는 중복 검사가 없습니다.
- 서버는 동일인·동일 조건·동일 시설의 반복 등록을 찾아 합치지 않습니다. 계정별 고유 등록 제한이나 중복 방지용 고유 인덱스도 없으므로 **건수는 고유 이용 인원과 다릅니다.**
- 과도한 요청을 줄이기 위해 서버가 식별한 접속 주소 기준으로 두 등록 API를 합쳐 1시간 30회 제한합니다. 단일 서버 프로세스의 메모리 제한이며 동일인 확인 기능은 아닙니다.
- 공개 수강 신청 누계는 표시된 강좌 집계기간을 사용하지만, 희망 등록 통계는 지역 기준으로 누적 기록을 집계합니다. 현재 데이터 버전이나 동일한 날짜 구간으로 자동 제한하지 않습니다.

## 간단한 예시

가정으로 수영·월수 18~20시 희망을 한 번 등록하면 지역 총건수는 1건 늘고, 월 18시·수 18시 통계는 각각 1건씩 늘어납니다. 같은 조건으로 다시 등록하면 2건이 될 수 있습니다. 이 2건을 지원 방안으로 불러왔을 때 인원 초기값이 2여도, 실제 이용 희망자가 2명인지 확인해야 합니다.
