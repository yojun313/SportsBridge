# AI 질문·자료 조회·답변 기록

기준: 2026-10-30 현재 코드 · 이용자 `/user/ask`, 담당자 `/agent`

자연어 질문을 받아 **서비스의 자료 조회·계산 도구를 실행하고, 그 결과를 AI가 문장으로 정리**하는 기능입니다. 지역 순위·후보 점수·배정 인원을 AI가 임의로 계산하는 방식은 아닙니다.

## 입력과 사용하는 자료

입력은 최대 2,000자의 질문과 이용자/담당자 구분입니다. 질문·조회 결과가 외부 AI API에 전달될 수 있으므로 개인 이름·연락처·가구 정보를 입력하지 않습니다. 모델·기능 사용 여부·비용 한도는 서버 설정을 따릅니다.

| 도구 | 읽는 자료·계산 | 답변에 제공하는 근거 |
|---|---|---|
| 지역·시설 확인 | 지역별 활용정보의 표준 지역 목록, 공개 가맹시설·전체 시설 목록 | 지역 코드·시설 ID·표기 후보 |
| 지역 현황·지역 비교 | 지역별 활용정보와 시설·강좌·이용현황의 집계 통계 | 시설 수·종목 수·시간대 비율·순위·지역 간 차이 |
| 강좌 조회 | 스포츠 강좌이용권 이용현황 + 이용시설 강좌 시간표 + 저장된 추출 정보 | 시설·강좌·요일·시간·월 수강료·기록월·확인 상태 |
| 가맹 검토 시설 조회 | 전체·공공·학교 시설, 가맹 목록 연결 결과, 안전점검·교통·이용 희망 | 후보·규칙 점수·근거·추가 확인 사항 |
| 지원 방안 구성 | 기존 강좌·상위 후보와 질문에서 추출한 집단·시간·비용·정원 | 시뮬레이션 입력 데이터. 담당자용만 사용 |
| 조합 시뮬레이션 | 위 입력과 서비스의 배정·조합 계산 엔진 | 현재 상태·예산 내 최선·개별 선택·결합 효과. 담당자용만 사용 |
| 출처 조회 | 현재 데이터 버전·기준일·출처/확인 상태 정의 | 자료의 출처와 해석 기준 |

새 원본을 인터넷에서 검색하는 도구는 없습니다. 현재 서비스에 반영된 데이터와 서버의 계산 함수를 사용합니다. 이용자 모드에는 지원 방안 구성·시뮬레이션 도구를 제공하지 않습니다.

## 질문에서 답변까지

1. **질문을 정리합니다.** 불필요한 제어 문자를 제거하고 앞뒤 공백과 길이를 정리합니다. 개인정보·개인별 지원 자격 판정 등의 일부 요청은 정해진 표현 규칙으로 먼저 차단합니다. 이때 모델·조회 도구를 호출하지 않습니다.
2. **질문 키워드로 조회 힌트를 붙입니다.** 저녁·주말·연령·지역 비교·예산·종목 등을 찾아 도구 선택 참고 문구를 만듭니다. 이 단계가 최종 답변이나 완전한 자연어 판정은 아닙니다.
3. **AI가 필요한 도구를 고릅니다.** 지역 표현이 있으면 지역 코드를 찾고, 강좌·지역 통계·후보 등 필요한 자료를 요청합니다. 실제 조회와 계산은 Python 서비스 함수가 수행합니다.
4. **결과를 받아 필요하면 다시 조회합니다.** 조회 결과를 다음 모델 요청에 전달합니다. 같은 도구를 같은 입력으로 반복 호출하는 것은 차단하고, 오래된 조회 결과는 일부를 줄여 전달합니다.
5. **답변을 점검합니다.** 도구 결과에 없는 숫자, 가맹·성과 확정 표현, 자료가 있는데도 확인 불가로 끝내는 답변 등을 검사해 다시 작성하도록 요청합니다. 최종 단계에서도 일부 근거 없는 숫자를 치환하고 단정 표현을 제거합니다.
6. **근거와 확인 사항을 붙입니다.** 도구 결과의 공공자료·규칙·AI 추출·확인값·가정 구분과 미확인 항목을 모읍니다. 화면에는 답변, 조회·계산 과정, 근거 카드, 처리 상태·사용량을 표시합니다.

AI가 만든 지원 방안도 실제 시설에 가맹·개설·예약을 실행하지 않습니다. 질문에 없는 정원·비용은 확인되지 않은 값으로 다루며, 후보 강좌의 계획 시간표 등 일부 값은 가정으로 구성될 수 있습니다.

## 조회 과정은 어떻게 표시하는가

| 단계 | 서버·브라우저 처리 |
|---|---|
| 질문 시작 | `/runs`로 실행 ID를 만들고 서버에서 답변 작업을 시작 |
| 진행 상태 | 서버 메모리에 도구 요청·결과·점검·사용량 이벤트를 보관 |
| 담당자 화면 | SSE로 이벤트를 받아 조회 과정 갱신. 실행 ID가 같은 이벤트만 표시 |
| 보조 확인·이용자 화면 | 약 4초마다 실행 상태를 조회. 이용자 모드는 담당자 SSE에 연결하지 않음 |
| 완료 | 최종 답변과 근거를 화면에 표시하고 입력을 다시 활성화 |

‘조회 과정’은 실행한 자료 조회·계산 단계와 요약이지 AI의 내부 사고 내용을 그대로 공개하는 기능이 아닙니다. 실행 상태는 프로세스 메모리에 제한된 수만 보관하므로 영구 기록과 다릅니다.

## 캐시와 답변 기록

- **담당자 답변 재사용:** 현재 데이터 버전·모드·앞뒤 공백을 제거한 질문이 같고, 이전 답변이 정상 완료되었다면 메모리 캐시의 답변을 재사용합니다. 재사용 시 모델을 새로 호출하지 않고 새 이력 행도 만들지 않습니다.
- **담당자 질의 기록:** 새로 실행한 결과를 `agent_history`에 저장합니다. `/history`에서 최근 기록을 읽어 이전 질문·답변을 펼칩니다. 사용자별 개인 기록함이 아니라 관리자용 공통 기록이며 당시 자료 기준으로 해석해야 합니다.
- **이용자 질문:** 관리자 답변 캐시와 `agent_history` 저장을 사용하지 않습니다. 다만 실행 중 질문·결과는 서버 메모리에 남을 수 있고, AI 호출의 입력 식별값·사용량·추정 비용은 별도 호출 기록에 저장될 수 있습니다.
- 서버 재시작으로 메모리 캐시·실행 상태는 사라질 수 있지만 DB에 저장된 담당자 이력·호출 기록은 별개입니다.

## 간단한 예시

“종로구 저녁 수영 강좌를 알려 주세요”라고 질문하면, 지역 확인 → 종로구 코드로 강좌 조회 → 18시 이후 수업 여부 확인 → 조회된 시설·요일·시간·요금을 문장으로 정리하는 흐름을 따릅니다. 현재 잔여석은 원본에 없으므로 예약 가능으로 확정하지 않습니다.

담당자가 인원·시간·정원·예산까지 제시하면 지원 방안을 구성하고 코드로 조합을 계산할 수 있습니다. 이용자 모드에서는 같은 질문을 해도 담당자용 시뮬레이션 도구를 제공하지 않습니다.

## 동작 한도와 결과의 한계

- AI 비활성·API 키 미설정 상태에서는 질문 기능을 사용할 수 없습니다. 기본 강좌 검색·지역 통계·직접 입력 시뮬레이션은 별도 기능입니다.
- 서버는 일일 추정 비용, 모델 반복 횟수·작업 시간, 도구별 실행 시간을 제한합니다. 한도에 도달하면 수집한 근거만으로 마무리하거나 미완료·오류 안내를 반환할 수 있습니다.
- 후검사는 숫자 문자열과 일부 표현을 비교하는 규칙입니다. 작은 수·시간·연도 등에 예외도 있으며, 숫자의 의미·단위·시설명·현재 상태까지 모두 검증하는 장치는 아닙니다.
- 코드 검사가 통과되어도 개인별 지원 자격·현재 모집·가맹 승인·정책 효과를 보장하지 않습니다. 답변의 출처·가정·확인 필요 항목과 실제 시설 안내를 함께 확인해야 합니다.
